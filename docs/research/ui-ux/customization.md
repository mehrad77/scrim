# Research: Customization and discoverability

**Question:** How can anyone open Scrim, find their way, and make it their own without putting a show at risk?

**Status:** research notes, October 2026. The decisions drawn from them are in [UX_PRINCIPLES.md](../../../UX_PRINCIPLES.md) and [DESIGN_SYSTEM.md](../../../DESIGN_SYSTEM.md); where these notes and those documents differ, the documents win.

Scrim today (repo): per-machine settings are ad hoc `localStorage` keys (audio devices, display assignments, public URL); the keymap is per show and a duplicate key only toasts; the Operator treats Esc as PANIC even inside text fields and the Editor forwards Esc to the running show when you are not typing; the Library has no templates beyond Demo. Motion preferences are in the [motion notes](motion.md).

## Findings

### 1. Task-shaped layouts you can always reset

- What: Premiere ships 16 task workspaces (Essentials for one monitor, Learning with tutorials beside the work), Save as New Workspace and Reset to Saved Layout. Blender workspaces are top-bar tabs saved in the .blend (Load UI opts out) and can become the startup default; its Editor Type selector, the first button of every area header, turns any area into any editor, even a second copy of one already open. Resolve switches whole pages in one click and gives Cut (speed) and Edit (full control) over one project. VS Code has Reset View Locations; JetBrains keeps layout global or per project plus Restore Default Layout.
- Evidence: Premiere — https://helpx.adobe.com/premiere/desktop/get-started/tour-the-workspace/what-are-workspaces.html , .../change-create-reset-workspaces.html; Blender — https://docs.blender.org/manual/en/latest/interface/window_system/workspaces.html , https://docs.blender.org/manual/en/latest/editors/index.html; Resolve — https://www.blackmagicdesign.com/products/davinciresolve; VS Code — https://code.visualstudio.com/docs/configure/custom-layout; JetBrains — https://www.jetbrains.com/help/rider/2024.1/Manipulating_the_Tool_Windows.html
- Apply to Scrim: Editor, all personas. The six tabs already are Resolve-style pages, so add no second workspace axis. Remember panel sizes and collapse state per page, per machine; View ▸ Reset layout (page / all) with an Undo toast. Few starter layouts, only where they differ: Editor "Essentials" (default laptop) and "Review" (director); Operator "Call" and "Monitor". A designer may embed an Operator layout in the show for the stage manager (Blender/JetBrains precedent), overridable locally. Editor-type switching only in bounded form: each Operator region picks among its own views (Audience / State / Media / Log), never arbitrary editors.
- Confidence: high

### 2. Collapse, focus, maximize-under-pointer

- What: Figma Minimize UI (⌘⇧\) collapses nav and both sidebars, the right panel returns on selection; Hide UI (⌘\) also hides the toolbar; one small forum thread (2 replies, the latest Sep 2026) asks Figma to restore independent left/right collapse, even as a preference. VS Code: Zen Mode (⌘K Z, double-Esc exits) and title-bar toggles for sidebars/panel. Blender: Ctrl+Space maximizes the area under the pointer, Ctrl+Alt+Space hides all chrome. Premiere: ` maximizes the panel under the cursor. JetBrains: Shift+Esc hides a tool window, Ctrl+Shift+F12 hides/restores all. Ableton is one fixed window where each region (Browser, Mixer, Info View) has an on-screen toggle, a View-menu item and a shortcut.
- Evidence: https://help.figma.com/hc/en-us/articles/41414918021271-Hide-or-minimize-the-UI; https://forum.figma.com/suggest-a-feature-11/bring-back-independent-left-right-panel-collapsing-as-in-ui2-42703; https://code.visualstudio.com/docs/getstarted/userinterface; https://docs.blender.org/manual/en/latest/interface/window_system/areas.html; https://helpx.adobe.com/premiere/desktop/get-started/tour-the-workspace/display-any-panel-full-screen.html; https://www.jetbrains.com/help/idea/tool-windows.html; https://www.ableton.com/en/live-manual/12/live-concepts/
- Apply to Scrim: Editor/Stage, art director. Header: independent left / right / bottom toggles plus Focus (canvas only); the Stage inspector reappearing on selection is Figma's pop-back. Add maximize-under-pointer for canvas and cue list. Never exit Focus or close overlays with Esc in the Operator (PANIC); toggle with the same key or a visible button.
- Confidence: high

### 3. Panel library pick: react-resizable-panels v4

- What: Scrim needs fixed topology with resize, collapse, persist and lock. Checked 8 Oct 2026:
  - **react-resizable-panels 4.14.3** (7 Oct; v4.0.0 16 Dec 2025, 93 v4 releases). API is `Group`/`Panel`/`Separator` (renamed from v3's `PanelGroup`/`PanelResizeHandle`, so older snippets will not compile). Sizes in px/%/rem/vh; `collapsible` + `collapsedSize` rail; `groupResizeBehavior="preserve-pixel-size"` keeps a 288px inspector at 288px on window resize; `disabled` on Group/Panel/Separator; `resizePreviewMode="separator"` drags an overlay and resizes on release; imperative `setLayout`/`collapse`/`resize`. Separators are focusable ARIA separators: arrows nudge 5 percentage points, Home/End, Enter collapses/restores, F6 cycles splitters; hit area 10px mouse / 20px touch. `useDefaultLayout({id, storage})` accepts any synchronous `getItem/setItem` store and saves the requested layout, so a small window never permanently shrinks panels (4.14.1). No dependencies, React 18/19, MIT, 5.4k stars, 1 open issue, ~43M weekly downloads, under shadcn's Resizable; maintainer-led by one author.
  - **dockview 8.4.1** (5 Oct): tabs, groups, floating, popout, `toJSON/fromJSON`, strong a11y (ARIA tabs, keyboard docking, live announcements); MIT core plus a commercial enterprise package; 3.5k stars, 92 open issues, ~0.5M weekly (dockview-react).
  - **FlexLayout 0.11.1** (26 Sep): JSON model, border panels, popout, layout undo, documented keymap; pre-1.0, 1.4k stars, 135 open issues, ~0.1M weekly.
- Evidence: https://github.com/bvaughn/react-resizable-panels (README, CHANGELOG, `lib/global/event-handlers/onDocumentKeyDown.ts`, `useDefaultLayout.ts`); https://react-resizable-panels.vercel.app/examples/collapsible-panels; https://dockview.dev/docs/advanced/accessibility/; https://github.com/dockview/dockview; https://github.com/caplin/FlexLayout; https://ui.shadcn.com/docs/components/resizable; registry.npmjs.org + api.npmjs.org
- Apply to Scrim: choose react-resizable-panels for Editor and Operator. Set `resizePreviewMode="separator"` on the Stage group so Moveable's canvas is not re-measured per pointer move. Persist via the existing guarded `readLocal/writeLocal` pattern (the hook's default `localStorage` access may throw when storage is blocked), keys `scrim.layout.<surface>`. Set `disabled` on every Group in Show mode so a bump in a dark booth cannot move a splitter. Skip dockview/FlexLayout for now: tab dragging, floating and popout mostly add ways to rearrange the Operator by accident, and popouts strain "the operator tab is the only runtime" _(inference)_. Revisit dockview if Editor users ask for free docking. No built-in collapse animation: drive `panelRef.resize()` from Motion or add a transition only for programmatic toggles _(inferred from docs, untested)_.
- Confidence: high on the pick; medium that docking is never needed

### 4. One command registry feeds palette, menus, tooltips, shortcut sheet

- What: Superhuman's rules: one shortcut everywhere that also closes it and restores focus; one palette for everything; every action exists as UI, shortcut and command; fuzzy search with aliases ("archive" shows "Mark Done (Archive)"); hide only irrelevant commands. Linear lets you act on a selection by shortcut, ⌘K or right-click, and its menu opens beside the clicked element. Figma Actions (⌘K, toolbar icon) even hosts Hide/Show UI and Keyboard shortcuts. Raycast's Action Panel (⌘K) lists actions for the selected item with ↵ primary. **cmdk 1.1.1** (14 Mar 2025; repo dip/cmdk, 13k stars, last push Oct 2025, ~55M weekly): unstyled `[cmdk-*]`, `keywords`, custom `filter`, `--cmdk-list-height` for animated height, fine to 2–3k items, React 18/19, powers shadcn Command. **React Aria Components 1.22.0** (8 Oct 2026) documents an Autocomplete command palette.
- Evidence: https://blog.superhuman.com/how-to-build-a-remarkable-command-palette/; https://linear.app/docs/select-issues; https://linear.app/changelog/2019-10-07-contextual-command-menu; https://help.figma.com/hc/en-us/articles/23570416033943-Use-the-actions-menu-in-Figma-Design; https://manual.raycast.com/action-panel; https://github.com/dip/cmdk; https://react-aria.adobe.com/Autocomplete
- Apply to Scrim: Editor and Operator Rehearsal. Create `commands.ts` with `{id, title, aliases, shortcut, when(ctx), run}`; menus, context menus, tooltips, the `?` sheet and key mapping all read it. Add a visible "Search ⌘K" pill in the Editor header, and keep every command reachable by a visible control. Include "Go to cue / scene" (sets standby, never fires). In Show mode the palette is off by default (no new key traps on the GO path), enabled as "Cue search" in Operator preferences; when open in the Operator it cannot close on Esc, so use ⌘K again, click-away or Backspace-on-empty. Use cmdk inside Scrim's own `<dialog>`, or React Aria if you adopt it for the missing Menu/Popover/Tooltip primitives.
- Confidence: high

### 5. Teach shortcuts where the eyes already are

- What: Superhuman shows the shortcut beside each result; Raycast shows each action's shortcut so you learn them over time; Figma shows them on hover and in a ⌃⇧? panel that highlights shortcuts you have used; Linear (2024) added a practice mode that disables pointer input; GitHub's `?` lists shortcuts for the current page; Apple shows an app's shortcuts while Command is held (visionOS). ExposeHK (CHI 2013, three studies): holding a modifier overlays hotkeys on commands, raising hotkey use and speed over pointing. The 2014 novice-to-expert survey: users persistently fail to adopt faster methods, so exposure must be active.
- Evidence: Superhuman and Raycast (above); https://help.figma.com/hc/en-us/articles/360040328653-Use-shortcuts-and-quick-actions; https://linear.app/changelog/page/8; https://docs.github.com/en/get-started/accessibility/keyboard-shortcuts; https://developer.apple.com/design/human-interface-guidelines/keyboards; https://doi.org/10.1145/2470654.2470735; https://doi.org/10.1145/2659796 (abstracts via OpenAlex)
- Apply to Scrim: Editor, Operator Rehearsal. A Tooltip primitive that always carries a `Kbd` hint; hold Alt/Option to overlay shortcuts on buttons; a `?` sheet scoped to the current surface with GO/Hold/Panic/standby first; "used" marks per machine; a Rehearsal keyboard drill (pointer disabled) to practise GO/Hold/Panic.
- Confidence: high for hints and overlay; medium for the drill

### 6. Keymaps: map in context, resolve conflicts, presets, protect PANIC

- What: VS Code: right-click any action ▸ Configure Keybinding, "Show Same Keybindings" for conflicts, Migrate Keyboard Shortcuts from other editors, layout-independent bindings. Premiere: key sets matching other apps, conflict warning with Undo/Clear, named saved sets. Blender: presets incl. Industry Compatible, export of only modified keys, first-run choice of what Spacebar does (Search suits newcomers). Raycast records hotkeys and aliases inline from the palette. Ableton Key/MIDI Map Mode highlights mappable controls on the live UI: click one, press a key or note, review in a Mapping Browser. QLab: GO is Space, Panic All is a double-tapped Esc that cannot be changed, duplicates are not blocked, optional "key up before re-arming GO". WCAG 2.1.4: single-character shortcuts must be off, remappable or focus-only.
- Evidence: https://code.visualstudio.com/docs/configure/keybindings; https://helpx.adobe.com/premiere/desktop/get-started/keyboard-shortcuts/customize-keyboard-shortcuts.html; https://docs.blender.org/manual/en/latest/editors/preferences/keymap.html; https://manual.raycast.com/command-aliases-and-hotkeys; https://www.ableton.com/en/live-manual/12/midi-and-key-remote-control/; https://qlab.app/docs/v5/general/keyboard-shortcuts/; https://www.w3.org/WAI/WCAG21/Understanding/character-key-shortcuts.html
- Apply to Scrim: Controls tab and Operator (designer, stage manager, performer). Replace the form with a Map mode over the real Operator UI: GO, Hold, Panic and triggers highlight; click, press key/pedal/MIDI. Conflicts become an inline Replace / Swap / Cancel naming the other command, not a toast. Esc PANIC stays non-remappable (QLab) but a second panic key is allowed. Presets: "Scrim default" and "QLab-style" (Space GO, P pause, [ ] pause/resume all, Esc panic); a slide-clicker preset (←/→/PgUp/PgDn, B to black out) is a suggestion _(unverified)_. Store `event.code` with the `key` label so [ ] and arrows survive non-US layouts; export keymaps as deltas. Single-key Editor tools get a "Single-key shortcuts" off switch.
- Confidence: high

### 7. Settings scope: show, machine, person, session

- What: QLab keeps Workspace Settings in the file (they travel, with selective import from a file, another open workspace or defaults; they include keyboard shortcuts, the double-GO guard and panic duration) and Preferences on the Mac (they never transfer). VS Code layers User and Workspace settings (some cannot be overridden) and Profiles that bundle settings, keybindings and more, with partial inheritance and export to file or link. JetBrains asks whether layout is shared or per project. Blender separates Preferences from the Startup file and the .blend's own UI.
- Evidence: https://qlab.app/docs/v5/general/qlab-preferences/; https://qlab.app/docs/v5/fundamentals/workspace-settings/; https://code.visualstudio.com/docs/configure/settings; https://code.visualstudio.com/docs/configure/profiles; https://docs.blender.org/manual/en/latest/getting_started/configuration/defaults.html
- Apply to Scrim (recommended model; no accounts, so "person" is an exported file):

| Scope       | Lives in                              | Travels                   | Customizable here                                                                                                                                                                                                                            |
| ----------- | ------------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Show**    | `.scrim`                              | with the file             | Key/MIDI/gamepad maps for GO, Hold, Panic, triggers (exists); GO guard (≥300 ms, longer allowed); optional default Operator layout and side tab; cue notes and colors                                                                        |
| **Machine** | `localStorage` / IndexedDB `settings` | stays on this browser     | Output-to-display and audio-bus devices, public URL; panel layouts per surface; UI scale, density, theme/accent/contrast; launch behavior; live thumbnails; dismissed hints, used-shortcut marks; motion setting ([motion notes](motion.md)) |
| **Person**  | `scrim-prefs.json`                    | by hand, checklist import | Editor keymap preset + overrides, appearance, palette favorites, saved templates                                                                                                                                                             |
| **Session** | memory                                | no                        | Tab, selection, zoom, Focus/maximize state, search text                                                                                                                                                                                      |

- Confidence: high

### 8. Preferences: small, searchable, resettable, context-first

- What: VS Code's Settings editor searches live, puts "Commonly Used" first, marks changed settings with a coloured bar, filters `@modified`, resets one setting from a gear menu, deep-links by URL, and hides advanced settings from search unless asked. Apple: minimize settings, pick good defaults, never ask for what can be detected, and keep task-specific options (show/hide parts of a view, reorder, filter) in the screen they affect. ⌘, opens settings in VS Code, QLab and Linear; Blender uses Ctrl+, and auto-saves preferences with Load Factory Settings.
- Evidence: https://code.visualstudio.com/docs/configure/settings; https://developer.apple.com/design/human-interface-guidelines/settings (text via Apple's JSON endpoint); https://qlab.app/docs/v5/fundamentals/workspace-settings/; https://linear.app/changelog/2019-10-07-contextual-command-menu (⌘, shortcut); https://docs.blender.org/manual/en/latest/getting_started/configuration/introduction.html
- Apply to Scrim: ⌘, opens a Preferences `<dialog>` with Appearance, Keyboard, Displays & Audio (badge "this machine"), Operator, Advanced; a search box; a dot on changed rows with per-row Reset and Reset all; save on change with Undo; Import/Export with a checklist (QLab). Detect displays and audio instead of asking. Move today's scattered per-machine fields here, but keep live controls where the task happens (Outputs panel, layout toggles).
- Confidence: high

### 9. Customize access first; few appearance knobs

- What: Mackay (51 users, four months): most people do not tune options and many skip customization entirely, since time spent customizing is time not working; the paper studies what triggers it. Page et al.: 92% of word-processor users customized something, mostly to reach frequent functions faster, and few touched appearance. Linear replaced 98 per-theme variables with three (base, accent, contrast) in LCH; raising contrast yields high-contrast themes automatically. VS Code density is Default or Compact with Restore Defaults; Figma's Interface Scale is Larger/Smaller/Reset and costs canvas space.
- Evidence: https://doi.org/10.1145/108844.108867; https://doi.org/10.1145/238386.238541 (abstracts via OpenAlex); https://linear.app/now/how-we-redesigned-the-linear-ui; https://code.visualstudio.com/docs/configure/custom-layout; https://help.figma.com/hc/en-us/articles/360049549913-Adjust-the-scale-of-the-Figma-UI
- Apply to Scrim: spend effort on access: right-click any control ▸ "Set shortcut…" and "Pin to quick bar", favorite commands, per-show keymap. Appearance: Theme (Dark default, Light, System), Accent (6–8 presets), Contrast (Standard/High), generated from the `@theme` ink ramp (e.g., `oklch()`), plus UI scale (90–125%) and density (Comfortable/Compact), which also fixes the 10–11px labels. `go`/`standby`/`live` stay fixed and always carry a text or icon cue. Offer customization at trigger moments (after a first rehearsal, on repeated reach-for), not at first launch.
- Confidence: medium (theme design is my recommendation; behavior studies are 1990s)

### 10. First run: three questions, templates, a disposable demo

- What: Blender's first launch swaps the splash for a quick setup (language, theme, keymap preset, mouse select, Spacebar action) that can all change later; the normal splash offers New File from templates, Recent, Open and Recover Last Session. QLab has five "At launch" choices (Launcher, restore recent, blank, new from default template, nothing) and saves any workspace as a template (⌘⇧N chooser). Premiere's Home screen shows more recent projects and fewer tutorials as you gain experience. Linear's start guide opens a demo workspace whose changes stay local and reset on refresh.
- Evidence: https://docs.blender.org/manual/en/latest/getting_started/configuration/defaults.html; .../interface/window_system/splash.html; https://qlab.app/docs/v5/general/qlab-preferences/; https://qlab.app/docs/v5/fundamentals/workspace-templates/; https://linear.app/docs/start-guide; Premiere overview (finding 1)
- Apply to Scrim: Library, anyone and creative author. Replace the lone Demo button with a "Start a show" gallery: Blank, Demo, 3–4 real starters (audience vote that branches, slides plus cues, performer button counter) and "Save show as template". A first-run card with at most three questions (known tool: QLab / PowerPoint / Figma / none; theme; GO key) sets the keymap preset and suggested template. Demo becomes a disposable copy with "Restore demo". Recent shows with "Resume last run" and "Recover" sit first.
- Confidence: medium-high

### 11. Pull, not push: contextual help and checklists, no auto tours

- What: NN/g (2023): tutorials are push revelations that interrupt, are forgotten and often skipped; contextual pull help works better; the one tutorial it praised (ArcGIS) made users do the task and sat in the sidebar instead of auto-starting. Vendor data (Chameleon 2024, ~300M interactions; the vendor sells tours): tours average 33.5% completion, five-step tours 21.6%, tours users chose to start 64%. Pre-completed checklist items raise completion (endowed progress, Nunes & Drèze 2006, consumer setting). Ableton ships Learn View (lessons with check marks, shown on first launch, closable, needs the internet) and Info View (hover for an element's name and function, `?` toggles, your notes saved in the Set).
- Evidence: https://www.nngroup.com/articles/onboarding-tutorials/; https://www.chameleon.io/benchmark-report-24; https://doi.org/10.1086/500480; https://www.ableton.com/en/live-manual/12/first-steps/
- Apply to Scrim: no auto-start tour. In the Demo add an offline Learn panel with five do-it steps (press GO in Rehearsal, edit a cue's text, scan the QR and vote, map a key, switch to Show mode), the first pre-checked, completion detected automatically. Add an Info strip (hover any control for one line plus shortcut; `?` toggles) and one-time contextual hints on first encounter, dismissible and recallable from Help. No hints in Show mode.
- Confidence: high

### 12. Empty states that report status, teach, and act

- What: NN/g (2021) gives empty states three jobs: system status, learning cues, direct paths to the first task (Datadog's empty favorites explains how to add one).
- Evidence: https://www.nngroup.com/articles/empty-state-interface-design/
- Apply to Scrim: Library (no shows ▸ template gallery); Cues (none ▸ "Drop media or add a first cue"); Interaction (no state ▸ recipe cards: "audience vote → branch", "performer button → counter"); Controls (none ▸ "Press a key to map GO"); Outputs (no displays ▸ "Detect displays, or open as a window"); Operator (no standby ▸ "Pick a cue; Space fires it"). The same copy feeds the Info strip.
- Confidence: high

### 13. Progressive disclosure: two levels, user-controlled, never adaptive

- What: Nielsen: show a few options first, the rest on request; two levels at most, a clearly labelled path, a split chosen from task analysis. Findlater & McGrenere (27 participants): static menus beat adaptive ones for speed, and most preferred user-controlled menus. McGrenere et al.: a field study found a toggle between a personalized and a full interface beat Word 2000's adaptive menus. VS Code hides advanced settings from search; Resolve splits Cut and Edit. Counterweight: expert features go unused (2014 survey), so hidden must be signposted.
- Evidence: https://www.nngroup.com/articles/progressive-disclosure/; https://doi.org/10.1145/985692.985704; https://doi.org/10.1145/503376.503406; https://code.visualstudio.com/docs/configure/settings
- Apply to Scrim: Interaction tab (921-line form), creative author vs pro. Level 1: recipe cards and a "When … then …" sentence builder; level 2: "More options" per action (timing, conditions) and "Advanced" (state types, expressions). Hide fields, never whole tabs (principle 4). Add a remembered Simple/Full toggle for the Stage inspector. The Operator never reorders or hides things based on usage.
- Confidence: high

## Top 5 recommendations

1. Adopt react-resizable-panels v4 as the only panel engine: per-page layouts saved per machine via a guarded storage adapter, collapsible rails, `preserve-pixel-size` inspectors, separator preview on the Stage, `disabled` Groups in Show mode, header toggles, Focus and Reset-with-Undo (1–3). Defer dockview.
2. Build one command registry and a ⌘K palette on cmdk (or React Aria Autocomplete) that also drives `Kbd` tooltips, context menus and a scoped `?` sheet; palette off by default in Show mode and never closed by Esc in the Operator (4, 5).
3. Adopt the Show / Machine / Person-as-file / Session model with a ⌘, Preferences dialog (search, changed markers, per-row Reset, checklist import/export) and fold the scattered per-machine fields into it (7, 8).
4. Replace tours with pull-based onboarding: three-question first run, template gallery, disposable Demo with an offline five-step checklist, Info strip, teaching empty states on all six surfaces (10–12).
5. Rebuild Controls as a Map mode on the live Operator UI with inline conflict resolution, "QLab-style" and default presets, non-remappable Esc PANIC and `code`-based keys; keep Interaction to two user-controlled disclosure levels (6, 13).
